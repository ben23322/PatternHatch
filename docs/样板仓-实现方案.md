## 3. 总体架构

两个组件（可合成一个 addon 发布）：

1. **样板仓部件**：带样板槽、隔离缓存（物品+流体）、催化剂槽、电路槽、ME 对接。
2. **兼容层**：Mixin 注入 GTCEu 基类（多方块 + 单方块两条路径）。

数据流：

```
ME 终端发起合成
  → AE 网络调用仓室 IInterfaceHost.pushPattern
  → 物品/流体按样板槽写入该槽隔离缓存
  → 机器（被补丁改造的基类）空闲时按样板优先级检查缓存
  → 命中：从该槽缓存取料（催化剂/电路不消耗）执行配方
  → 产物进机器输出
```

## 5. 关键实现要点

### 5.1 仓室部件（MetaTileEntityPatternHatch）

- 参考 GTCEu `MetaTileEntityInputBus` 的注册方式与机器识别方式（实现
  `IItemHandler` / `IFluidHandler` 并正确接入部件枚举）。
- 内部持有：
  - `PatternSlotEntry[36]`：每项含样板、`PatternCacheInventory`、`PatternCacheFluidHandler`；
  - `ItemStackHandler[4]` 催化剂槽；
  - `ItemStackHandler[1]` 虚拟电路槽。
- NBT 持久化：样板、缓存、槽位全部落盘。

### 5.2 AE2 对接（核心难点）

- 实现 **`appeng.helpers.IInterfaceHost`**（rv6 在 `appeng.helpers` 包）：
  - `getPatterns()`：返回仓室内样板，供 ME 终端显示与合成计划；
  - `pushPattern(...)`：AE 发起合成时按**槽位**把物品与流体写入对应隔离缓存；
  - 网格接入：正确实现 `IGridBlock` 相关检测，使仓室在 ME 网络上表现为接口。
- 流体样板：AE2 rv6 原生支持流体合成样板，`ICraftingPatternDetails` 中可取得流体输入，按槽路由即可。
- 备选：复用 `DualityInterface` 内部逻辑减少自研，但需锁定 appeng 6.x 版本。

### 5.3 兼容补丁（Mixin）

- `MixinRecipeMapMultiblockController`：
  - 采用**“活动槽视图”方案**，不重写原版配方引擎：
    1. 机器空闲时，补丁按样板优先级挑选下一个可执行槽位，记为“活动槽”；
    2. `getInputInventory()` / `getInputFluidInventory()` 重定向为“活动槽缓存 +
       催化剂槽 + 电路槽”的合并视图；
    3. 原版 findRecipe / 消耗流程照常运行——`notConsumed` 输入（催化剂、电路）
       只匹配不消耗，普通输入从活动槽缓存扣除；
    4. 配方完成（机器回到空闲）后解锁活动槽，进入下一个槽位；
  - 无样板仓时走原逻辑（透明）。
- `MixinRecipeMapWorkable`：单方块机器等价逻辑。
- 注入点的精确位置（空闲判定、进度状态）**以 TJ fork 反编译源码为准**，这是 M3 第一步。
- MixinBooter：在 `mixins.json` 声明目标类，遵循 MixinBooter 10.7 的加载约定。

### 5.4 催化剂 / 电路匹配

- 催化剂：4 个槽的物品以 `notConsumed` 方式参与 `RecipeMap` 配方匹配，不消耗。
- 电路：配方电路输入与电路槽物品按 GTCEu 电路约定匹配，不消耗；电路槽空则含电路配方不执行。

### 5.5 GUI / 网络

- 界面分区：样板槽区（4×9）、缓存查看区（物品 + 流体）、催化剂/电路槽区。
- 按钮：“返还物料到 AE”“清空缓存”。
- 缓存变化经自定义网络包同步（服务端权威）。

## 8. 测试清单（单人创造模式）

1. 仓室装上大型化学反应釜 → 放入含流体输入/输出的样板 → ME 终端可见 → 发起合成。
2. 验证物品与流体进入**各自槽位**缓存，多槽同时执行不串料。
3. 压膜机/组装机装仓室 → 单方块路径验证。
4. 放催化剂（透镜等）与电路板 → 含对应输入配方执行且不消耗。
5. “返还物料到 AE”将剩余物品/流体写回 ME。
6. 断电 / 重载存档后样板、缓存、槽位状态保持。
7. 不带仓室的机器行为与安装前一致（回归）。

## 9. 风险与备选

- **Mixin 注入点差异**：TJ fork 可能改动 GTCEu 基类，注入位置以 fork 反编译源码为准；若注入脆弱，切路线 2。
- **AE2 rv6 流体样板细节**：`pushPattern` 的流体路径需实测；备选为自研最小 pattern 提供逻辑。
- **单方块与多方块执行路径不同**：需要两处补丁，分 M3/M4 验证。
- **堆叠上限**：1.12.2 为 int 上限（21 亿），实际影响可忽略。
- **流体罐数量**：默认每槽 4 罐，配方流体输入超过 4 种时可调大。
